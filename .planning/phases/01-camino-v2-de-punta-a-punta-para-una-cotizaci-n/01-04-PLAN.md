<objective>
Cerrar el camino: la cotización v2 sale a la red como un POST con cuerpo JSON, autenticada por
header portador, con el código de entidad en su header dedicado y sin una sola credencial en la
URL. Y dejar el cableado armado exclusivamente en el punto de entrada.

Propósito: es el último tramo de la rebanada. Después de este plan, un operador con las
variables de v2 configuradas ejecuta `node index.js get_tax archivo.json --api-version=v2` y la
corrida termina de punta a punta; y el mismo operador, invocando sin flags, sigue obteniendo la
petición v1 exactamente igual que antes. Las dos cosas quedan demostradas por la misma prueba de
recorrido completo, sin red y sin credenciales.

Salida: `SynexusApiClient` funcionando, el grafo de dependencias completo en `index.js`, y la
documentación del repositorio al día con el selector de contrato.
</objective>

<el_header_de_entidad_ya_esta_decidido>
**El header correcto es `X-Synexus-Entity`. No `X-Syntax-Entity`.** No elegir por parecido y no
volver a abrir la pregunta.

La colección de Postman de este repositorio trae los dos nombres porque fue escrita anticipando
el cambio de marca, con el nuevo desactivado. Esa colección quedó desfasada: el cambio ya ocurrió
del lado del proveedor. La referencia de API documenta el nombre anterior porque es previa al
cambio de marca. Lo que decide es una petición real contra staging, del 9 de septiembre de 2026,
que usó `X-Synexus-Entity` y devolvió 200 con cuerpo completo. Una respuesta real gana sobre
documentación desfasada.

Poner el nombre del header como propiedad de instancia asignada en el constructor —igual que
`validOperations` en el validador— para que sea greppable y sustituible desde una prueba, y para
que el día del siguiente cambio de marca haya un solo lugar que tocar.
</el_header_de_entidad_ya_esta_decidido>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| nexgen → API del proveedor sobre TLS | La llave portadora cruza esta frontera en cada petición v2 |
| objeto de error de axios → salida estándar y archivos de log | El error de axios lleva la petición completa, headers incluidos; imprimirlo entero filtraría la llave |
| punto de entrada → capas | Un cableado incompleto podría dejar una capa v2 sin construir y producir un fallo confuso |
| documentación del repositorio → operador | Un ejemplo con una credencial real quedaría versionado para siempre |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | credencial en la URL | mitigate | La llave viaja únicamente en `Authorization: Bearer`. Prueba que afirma que la URL no contiene `code=`, `key=`, `token=` ni ninguna subcadena de la llave (CONN-02) |
