<objective>
Construir la red de seguridad de toda la fase: un runner de pruebas que corre con un solo
comando, sin `.env`, sin credenciales y sin acceso a la red, y un conjunto de pruebas que
congelan el comportamiento observable del camino v1.

Propósito: `COMP-01` exige que v1 conserve exactamente su comportamiento actual. Los cuatro
planes siguientes modifican `src/config/index.js`, `src/cli/taxCommandHandler.js` y
`src/validators/taxValidator.js` — archivos que v1 usa. Sin estas pruebas, cada una de esas
modificaciones se hace a ciegas. Este plan es lo único que convierte "v1 no se movió" de
una afirmación a un hecho comprobable.

Salida: `npm test` verde, con el camino v1 congelado en método HTTP, URL resuelta,
mecanismo de autenticación y mensajes de error.
</objective>

<decision_de_diseno>
`01-CONTEXT.md` establece que las pruebas no pueden hacer `require` de `src/config` porque
ese módulo **lanza al cargarse** cuando faltan variables de entorno. `tests/setup.js`
elimina exactamente esa causa: fuerza `BASE_URL`, `API_CODE` y `OUTPUT_DIR` a valores
ficticios antes de que Jest evalúe cualquier archivo de prueba.

Con ese mecanismo en pie, `tests/v1Freeze.wire.test.js` **sí** hace `require('../src/config')`,
y debe hacerlo: congelar "la URL resuelta" de v1 es imposible sin el `Config` real —
duplicar `getEndpointUrl` en la prueba congelaría la copia, no el original.

Lo que sigue intacto del `CONTEXT.md`: nunca se requiere `index.js` (ejecuta `main()` al
cargarse), y los colaboradores se sustituyen con objetos literales, no con mocks de
framework.
</decision_de_diseno>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| suite de pruebas → red | Una prueba mal escrita podría emitir una petición HTTP real contra un host de producción |
| máquina del desarrollador (`.env`) → suite | Un `.env` real presente localmente podría alimentar credenciales verdaderas a la suite y volverla no determinista |
| repositorio → git | Un archivo de prueba en un directorio ignorado quedaría fuera de git sin aviso, dejando la red de seguridad ausente en el servidor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `tests/setup.js` ↔ `.env` local | mitigate | `tests/setup.js` **sobreescribe** `API_CODE`, `BASE_URL` y `SYNEXUS_API_KEY` con valores ficticios antes de cualquier `require`; `dotenv` no repone lo ya presente. Ninguna credencial real entra a la suite |
