<objective>
Hacer diagnosticable el camino v2: que toda corrida —exitosa o fallida— deje registrado el identificador
de petición que devuelve el proveedor (es lo que pide para levantar soporte), y que los errores del
contrato v2 se distingan por su código estable y no por el texto del mensaje, con mensajes en español que
le digan al operador qué pasó y qué hacer. La cancelación, cuyos errores vienen sin `code`, se clasifica
por status HTTP.

Propósito: cuando algo falle contra staging (Fase 3) o en producción, el operador tiene en pantalla y en
`logs/log_<fecha>.log` el `request_id` del proveedor y un mensaje que nombra el código; y ningún cambio de
redacción del proveedor cambia el comportamiento de nexgen.

Salida: `SynexusApiClient` con `_extractProviderRequestId`, `_describeCalculationError`,
`_describeCancelError`, la línea de éxito y los logs con `request_id=`; `createAxiosResponse` con headers;
pruebas unitarias y de recorrido para los dos requisitos.
</objective>

```javascript
// tests/helpers/fakes.js
createAxiosResponse(status, data, headers)
//   headers opcional, por omisión {}. axios entrega los nombres de header en MINÚSCULAS:

//   1. response.data.meta.request_id       (cuerpo de ÉXITO del cálculo)          — preferido
//   2. response.data.request_id            (cuerpo de ERROR del cálculo)
//   3. response.headers['x-request-id']    (todos los endpoints, también la cancelación)
//   Acceso defensivo: data puede ser null o cadena; headers puede faltar en un doble de prueba.
//   Sólo se devuelve si es cadena no vacía.

_describeCalculationError(status, data, headers)   // -> string en español; ramifica por data.code
_describeCancelError(status, data)                 // -> string en español; ramifica por status

// firmas
_handleResponse(response, url, operation)          // sin cambios de firma
_handleError(error, url, operation, requestBody)   // gana requestBody: la llave propia de nexgen como respaldo
```

Línea de éxito (sustituye a `SUCCESS: ${operation} - Status: ${response.status}`):
```
SUCCESS: ${operation} - Status: ${response.status} - request_id=${id}
   id = _extractProviderRequestId(response) || 'no informado por el proveedor'
```

Mensaje lanzado por `_handleResponse` cuando `response.status >= 400` (la respuesta resolvió: 4xx):
```
cálculo con data.code (cadena):  Error HTTP ${status} (${code}): ${descripción} - request_id=${id}
cálculo sin code:                Error HTTP ${status}: ${JSON.stringify(data) | statusText} - request_id=${id}     (molde de v1 + id)
cancelación (operation === 'cancel_tax'):  Error HTTP ${status}: ${descripción} - request_id=${id}
   id = _extractProviderRequestId(response) || 'no informado por el proveedor'
logger.error: `${errorMsg} - URL: ${url} - Operation: ${operation}` + (data.docs_url ? ` - docs_url: ${data.docs_url}` : '')
   docs_url va SÓLO al log (apunta a un host que no resuelve; no se le dice al operador que lo abra)
El Error lanzado lleva dos propiedades propias: providerResponded = true y providerRequestId = id | null,
para que _handleError (que lo recibe por el catch del molde) sepa que el proveedor SÍ respondió.
```

Catálogo del cálculo — `descripción` por `data.code`; si `typeof data.message === 'string'`, se le añade al
final ` Mensaje del proveedor: "${data.message}"` (citado, nunca interpretado):
```
invalid_key              La llave SYNEXUS_API_KEY fue rechazada por el proveedor. Verifique que sea la llave del ambiente al que apunta SYNEXUS_BASE_URL.
tax_code_missing         Una línea del carrito no trae tax_code; el proveedor rechaza toda la petición. Corrija la extracción del ERP.
idempotency_key_conflict Ya existe una petición con la misma llave de idempotencia y un cuerpo distinto: el archivo cambió entre corridas. No se reintenta; requiere revisión humana.
invoice_stale_object     La factura cambió mientras el proveedor la procesaba (conflicto de concurrencia). Vuelva a ejecutar la operación.
rate_limited             El proveedor limitó la tasa de peticiones. Reintente en ${headers['retry-after']} segundos.
                         (sin header:) El proveedor limitó la tasa de peticiones. Reintente en unos segundos.
cart_empty               El carrito está vacío: el archivo no trae líneas en cart.
validation_error         El proveedor rechazó el cuerpo por validación: ${detalles}
                         detalles = data.details (arreglo) unido con '; ' — cadenas tal cual, objetos con JSON.stringify — o 'sin detalles'
cualquier otro código    El proveedor devolvió el código "${code}".
```

Catálogo de la cancelación — `descripción` por `status`; mismo sufijo ` Mensaje del proveedor: "${data.message}"`
cuando `data.message` es cadena. **Nunca se ramifica por el texto de `message`.** Si el cuerpo de una cancelación
trajera `code`, se ignora: la cancelación se clasifica por status.
```
400   La cancelación fue rechazada: el cuerpo no es válido para el proveedor.
404   La factura a cancelar no existe en el proveedor: verifique invoice_id y customer_id, y que la factura se haya confirmado contra este mismo ambiente.
409   La cancelación chocó con otra operación en curso sobre la misma factura.
422   El proveedor no puede cancelar esta factura: probablemente ya está cancelada o nunca se confirmó.
otro  La cancelación falló con HTTP ${status}.
```

`_handleError(error, url, operation, requestBody)` — el identificador para soporte (dentro del bloque de
diagnóstico, después de `Timestamp:`), y en `detailedLog`:
```
providerId = error.response ? _extractProviderRequestId(error.response) : (error.providerResponded ? error.providerRequestId : null)
ownId      = requestBody && typeof requestBody.request_id === 'string' && requestBody.request_id.length > 0 ? requestBody.request_id : null
nota =
  (error.response || error.providerResponded) -> `request_id=${providerId || 'no informado por el proveedor'} (del proveedor)`
  ownId                                       -> `request_id=${ownId} (generado por nexgen; el proveedor no respondió)`
  en otro caso                                -> 'request_id=ninguno (la cancelación no lleva llave y el proveedor no respondió)'
console.error(`Identificador para soporte: ${nota}`)
detailedLog = `${errorMsg} - Operation: ${operation} - URL: ${url} - ${nota}`
```
`error.response` se lee sólo por `status`, `data`, `statusText` y `headers`. Sigue prohibido tocar `error.config`,
`error.request` (más allá de su presencia), `error.toJSON` y `response.config`/`response.request`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| respuesta de error del proveedor → consola y `logs/log_<fecha>.log` | El cuerpo del error se imprime y se registra; `response.config`/`error.config` llevan los headers de la petición y NUNCA deben cruzar |
| texto del `message` del proveedor → decisión de nexgen | Si nexgen decidiera por el texto, un cambio de redacción del proveedor cambiaría el comportamiento sin aviso |
| `docs_url` del proveedor → operador | Apunta a un host que no resuelve; abrirlo a ciegas no aporta y podría llevar a un host equivocado |
| identificador de petición → soporte del proveedor | Sin él, un fallo en producción no se puede levantar con el proveedor |
